# Copilot Studio Agent 部署指南

## 概述

本指南详细说明了如何在 Microsoft Copilot Studio 中部署广州PMO管理Agent。

---

## 前置条件

- [ ] Microsoft Copilot Studio 账户
- [ ] 管理员或开发者权限
- [ ] 基础的Agent配置知识
- [ ] 访问本仓库的所有文件

---

## 部署步骤

### 步骤 1: 创建新的Agent

1. 登录 **Copilot Studio**
2. 点击 **创建** → **新建Agent**
3. 输入以下信息:
   - **Agent名称**: 广州PMO管理助手
   - **描述**: 为广州Site GTS技术运营团队提供专业的项目管理支持
   - **语言**: 中文(简体)
   - **类别**: 业务应用

4. 点击 **创建**

### 步骤 2: 配置System Prompt

1. 打开Agent的 **设置** → **指令**
2. 在 **System Prompt** 中复制以下内容:

```
你是一个专业的项目管理办公室(PMO)助手，专门为广州Site GTS技术运营团队提供全面的项目管理支持。

## 核心职责

### 1. 项目规划
- 帮助制定项目章程和范围说明书
- 创建工作分解结构(WBS)
- 制定项目进度计划
- 预估项目成本

### 2. 项目执行与监控
- 跟踪项目进度和关键指标
- 生成定期的项目报告
- 监控预算执行情况
- 识别偏差并提出纠正措施

### 3. 风险管理
- 识别项目风险
- 评估风险的概率和影响
- 制定风险应对计划
- 监控风险状态

### 4. 资源管理
- 优化资源分配
- 解决资源冲突
- 提升团队效率
- 跟踪资源利用率

### 5. 干系人管理
- 分析干系人需求
- 制定沟通计划
- 提供定期更新
- 处理冲突和问题

## 工作方式

1. **收集信息**: 通过提问理解项目的具体情况
2. **分析评估**: 基于PMBOK标准和最佳实践进行分析
3. **提供建议**: 给出专业的、数据驱动的PMO管理建议
4. **跟踪执行**: 定期跟踪建议的实施效果并优化

## 通信原则

- 使用简体中文进行专业沟通
- 提供结构化的分析和建议
- 包含具体的数据支撑和量化指标
- 明确的行动计划和时间表
- 可追溯的决策依据
- 主动识别和预警潜在风险

## 遵循标准

✓ PMBOK第六版标准
✓ 敏捷项目管理原则
✓ 数据驱动决策
✓ 透明和及时沟通
✓ 持续改进文化
```

3. 点击 **保存**

### 步骤 3: 上传知识库

#### 3.1 创建知识库集合
1. 进入 **知识库** 标签
2. 点击 **添加知识库**
3. 选择 **上传文件**

#### 3.2 上传文档文件
依次上传以下文件:

**优先级 1 (必需)**:
- [ ] `agent-prompt.md` - Agent核心提示词
- [ ] `docs/pmo-guidelines.md` - PMO管理指南
- [ ] `docs/best-practices.md` - 最佳实践指南

**优先级 2 (模板)**:
- [ ] `templates/project-charter.md` - 项目章程模板
- [ ] `templates/weekly-report.md` - 周报模板
- [ ] `templates/risk-register.md` - 风险登记表模板
- [ ] `templates/change-log.md` - 变更日志模板

**优先级 3 (参考)**:
- [ ] `examples/sample-projects.md` - 示例项目

### 步骤 4: 配置Agent能力

#### 4.1 添加操作(Actions)
1. 进入 **能力** → **操作**
2. 添加以下操作:

**操作 1: 创建项目计划**
```
名称: 创建项目计划
描述: 协助创建新项目的详细规划
输入参数:
  - 项目名称 (文本)
  - 项目目标 (文本)
  - 预期工期 (数字, 单位:月)
  - 预算 (数字, 单位:万元)
输出: 项目计划文档
```

**操作 2: 生成进度报告**
```
名称: 生成进度报告
描述: 生成项目的周期性进度报告
输入参数:
  - 项目ID (文本)
  - 报告周期 (选择: 周/月/季度)
  - 完成率 (数字, 0-100%)
输出: 进度报告文档
```

**操作 3: 风险评估**
```
名称: 风险评估
描述: 分析和识别项目中的潜在风险
输入参数:
  - 项目ID (文本)
  - 风险类别 (选择: 技术/进度/成本/质量/其他)
输出: 风险评估报告
```

**操作 4: 资源优化**
```
名称: 资源优化
描述: 优化项目资源分配
输入参数:
  - 项目ID (文本)
  - 资源类型 (文本)
  - 约束条件 (文本)
输出: 优化建议
```

#### 4.2 连接外部系统
1. 进入 **集成** 标签
2. 连接以下系统(如适用):
   - **Microsoft Teams** - 用于消息通知
   - **SharePoint** - 用于文档存储
   - **Project for Web** - 用于项目数据同步
   - **Power BI** - 用于数据可视化

### 步骤 5: 测试Agent

#### 5.1 基础功能测试
在 **测试** 窗格中输入以下测试用例:

```
测试 1: 启动对话
输入: "你好，我需要帮助管理一个新项目"
期望: Agent自我介绍并询问项目信息

测试 2: 项目规划
输入: "帮我制定一个3个月的系统迁移项目计划，涉及200人天工作量"
期望: Agent生成详细的项目规划

测试 3: 风险识别
输入: "分析这个项目中的技术风险"
期望: Agent识别并评估风险

测试 4: 进度报告
输入: "生成本周的项目进度报告，完成率是70%"
期望: Agent生成结构化的进度报告
```

#### 5.2 性能测试
- 响应时间: < 3秒
- 答案质量: 准确、结构化、数据驱动
- 中文理解: 准确理解复杂的中文需求

### 步骤 6: 发布Agent

#### 6.1 最终检查
- [ ] 所有提示词已配置
- [ ] 知识库文件已上传
- [ ] 操作和集成已连接
- [ ] 测试通过

#### 6.2 发布
1. 点击 **发布** 按钮
2. 选择部署环境:
   - **草稿** - 测试环境
   - **已发布** - 生产环境
3. 点击 **确认发布**

#### 6.3 获取访问链接
1. 复制Agent的 **分享链接**
2. 分发给团队成员

## 配置详情

### agent-config.json 说明

```json
{
  "agentName": "广州PMO管理助手",           // Agent显示名称
  "agentId": "gzpmo-agent-001",             // 内部标识
  "version": "1.0.0",                       // 版本号
  "description": "...",                     // 功能描述
  "language": "zh-CN",                      // 语言设置
  "capabilities": [...],                    // 核心能力列表
  "knowledgeBases": [...],                  // 知识库配置
  "actions": [...],                         // 可执行操作
  "integrations": [...]                     // 集成系统
}
```

### agent-instructions.json 说明

定义了Agent的详细指令和行为参数:
- `system_instructions` - 核心系统指令
- `functional_capabilities` - 功能模块
- `interaction_patterns` - 交互模式
- `knowledge_domains` - 知识领域
- `context_awareness` - 上下文理解
- `error_handling` - 错误处理策略

## 使用示例

### 场景 1: 新项目启动

**用户输入**:
```
我需要启动一个新的核心系统迁移项目，
预计3个月，涉及15个团队成员，预算500万元。
请帮我制定详细的项目计划。
```

**Agent响应流程**:
1. 确认理解项目信息
2. 提问获取更多细节(目标、风险、关键里程碑)
3. 生成项目章程
4. 制定WBS和进度计划
5. 识别主要风险
6. 提供实施建议

---

### 场景 2: 周期性报告

**用户输入**:
```
生成本周的项目进度报告。
已完成: 需求分析、方案设计
进度: 70%
主要问题: 某个模块性能测试未通过
```

**Agent响应流程**:
1. 整理项目信息
2. 计算关键指标
3. 分析偏差原因
4. 提出改善建议
5. 预测完成日期
6. 生成可视化报告

---

### 场景 3: 风险管理

**用户输入**:
```
我们项目遇到了一些技术风险，
包括第三方API不稳定和数据库性能问题。
请帮我评估和制定应对计划。
```

**Agent响应流程**:
1. 识别具体的风险
2. 评估概率和影响
3. 绘制风险矩阵
4. 制定分级应对计划
5. 建议监控策略
6. 提供应急预案

## 故障排除

### 问题 1: Agent 不响应

**症状**: Agent长时间无响应  
**解决方案**:
1. 检查知识库连接状态
2. 验证API端点是否可用
3. 查看错误日志
4. 重新发布Agent

### 问题 2: 答案质量差

**症状**: Agent的回答不准确或不相关  
**解决方案**:
1. 审查System Prompt
2. 检查知识库文件
3. 测试不同的输入方式
4. 更新训练数据

### 问题 3: 中文理解问题

**症状**: Agent无法理解中文输入  
**解决方案**:
1. 确认语言设置为中文(zh-CN)
2. 检查输入是否为简体中文
3. 提供更清晰的表述
4. 使用规范的项目管理术语
